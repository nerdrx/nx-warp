# Next rate-growth gate design

Read-only comparison of frozen B and C. B holds unconfirmed increases only while `steady && !forced` ([B cpp](source/confirmed-B/server/driver/bitrate_controller.cpp), lines 1362–66), missing the 38–46 probe-phase burst. C caps every native upward target outside startup using current or post-peak p90 ([C cpp](source/growth-bounded-C/server/driver/bitrate_controller.cpp), lines 1362–72). C removes that burst in its retained virtual trace; root replay shows delayed 20s recovery (20.833→23.9s), unchanged 3s recovery with a 625→425 Mbit/s dip, and a 47 bps rounding difference in 126 rows of the 300 Mbit/s collapse trace (timing, estimate and states unchanged). These are reported results, not a replay here.

Next gate: activate the guard only for a material max/p90 split, e.g. `bw / s.rate >= 1.6`; below it preserve B's growth and probe behavior. Above it, cap only positive growth at the p90-derived target, floored at current bitrate. Keep forced probe-exit drain separate. This may preserve B's ordinary recovery without C pulling an unconfirmed target below current; it is unvalidated.

Avoid the mutable peak epoch: `rate > old_peak` resets its timestamp on any strict increase ([B cpp](source/confirmed-B/server/driver/bitrate_controller.cpp), lines 479–83), so tiny 1-bps peaks can keep confirmation stale. Recompute max/p90 divergence from the existing estimator and fresh window. Test all 47 probe offsets plus no-burst, 3/5/10/20s rises, and 300 Mbit/s collapse; track full targets and recovery. Reject if B's 3/20s recovery regresses, a growth-only cap lowers current bitrate, or the 50 Mbit/s excursion remains. Risk: `s.rate` is noisy/coalesced, so validate the 1.6 threshold before changing source.
