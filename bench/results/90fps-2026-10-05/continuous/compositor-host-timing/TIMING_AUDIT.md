# Compositor host-timing audit

Audited clean source `2cfb14faca86d6aff5826549e76238bfd06c8dde` (`server/compositor/compositor.cpp`, `server/driver/wivrn_session.cpp`, `server/compositor/pacer.cpp`, `server/encoder/video_encoder.cpp`). No source edits or runtime/GPU actions.

`WIVRN_DUMP_TIMINGS` opens the CSV in `wivrn_session` at `server/driver/wivrn_session.cpp:413-417`. `dump_time()` writes only when that stream is open, under `csv_mutex`, but also always emits a trace instant (`:1525-1532`). `layer_commit()` already emits `begin` at `server/compositor/compositor.cpp:849`, after its early encoder/session guards, pending-fence poll and image acquisition; the call currently reads the monotonic clock even if CSV is disabled. Thus it is not a commit-entry timestamp. GPU query spans at `:854-855`, `:998`, `:1011`, `:1112`, `:1142` measure GPU execution stages, not the CPU recording/submission/wait gaps.

The unmeasured host work that matters is around `layer_commit()` (`:809-827`, `:851-1162`, `:1170-1184`, `:1194-1220`, `:1230-1270`): zero-timeout pending-fence poll, image acquisition, command recording, queue-lock acquisition and `submit2`, encoder `present_image` dispatch, timeline wait, query-result wait, then garbage collection. In particular `query_pool.getResults(...eWait)` is a second possible host wait after the timeline wait (`:1248-1262`). The encoder loop calls `present_image` for each active stream after submission (`:1197-1217`); the base path itself can wait for a busy slot (`server/encoder/video_encoder.cpp:698-735`). The fence poll at `compositor.cpp:813` has timeout zero: record it as a nonblocking poll and distinguish timeout/drop from successful retirement, not as a blocking wait.

Minimal measurement recommendation: piggyback on the already-open `feedback_csv` path; add an immutable `dump_timings_enabled()` predicate for the compositor. Branch before every *new* monotonic read, leaving disabled frames with no added clocks or formatting. Reuse the existing `begin` timestamp as the start of command recording. When enabled, take local timestamps only at stage boundaries: acquire start/end; `cmd_pool.reset()` through `cmd.end()`; queue-lock wait separately from `submit2` call/submit scope; the whole encoder-present loop; timeline wait; query `getResults`; and garbage collection. Time the pending-fence poll only when a pending fence exists, and retain its timeout/success outcome. Keep the measurements in a fixed local struct and emit CSV rows only after all measured intervals (including GC) finish; on early timeout/drop, emit the pending-poll outcome after the poll returns and before returning. This prevents CSV mutex/flush and trace work from entering later measured intervals. Use monotonic duration nanoseconds in an extra CSV field; do not infer GPU time from host intervals.

Frame join: `predict_frame()` sets `frame.waited.id` to the pacer ID (`compositor.cpp:513-541`); `pacer::predict()` stores that same ID beside `desired_present_time_ns` (`pacer.cpp:96-123`); `present_to_info(desired_present_time_ns)` returns the matching record (`pacer.cpp:196-205`), and its `info.frame_id` is passed to every encoder (`compositor.cpp:1194-1216`). `video_encoder::encode()` carries that ID into shard/frame feedback and existing `encode_begin/end` and `send_begin/end` rows (`video_encoder.cpp:814-858, 899-910, 1072-1090, 1137-1168`). Therefore successful-commit timing rows should use `info.frame_id` to join `frame_bytes`, encoder, and headset `feedback_spans` rows. The XRT `frame.rendering.id` is seeded from the same predicted ID; retain it as a separate `xr_frame` extra if desired, rather than assuming the two namespaces always match. Early rejected commits occur before `present_to_info`; label their rows with the compositor/pacer frame ID and an explicit outcome.

This is a measurement design only. It does not claim that a measured host wait is GPU execution or end-to-end latency, and it does not cover encoder-worker work beyond synchronous `present_image` dispatch; existing encoder/send rows provide those later stages.
