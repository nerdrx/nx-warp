These tests do not couple all probe bytes to serialized paired-eye frame deadlines.
- **Probe/recovery admission and bounds:** `tests/bitrate_aimd_loss_only_test.cpp:87-166` checks deep recovery under clean conditions and denies it for over-threshold span, late frames, or loss; persistent loss remains bounded. `tests/bitrate_radio_test.cpp` Parts A–I (root log: 50 checks) checks radio degradation holds probes and its release/recovery paths. The BBR radio cases in `bitrate_bbr_test.cpp:538-621` cover the same general policy class.
- **Native/multi-stream BBR rate accounting:** `tests/bitrate_bbr_test.cpp:233-323` explicitly tests one stream, overlapping, sequential, partial, gapped, unequal, untimed, zero-span, reversed, chained and zero-byte/long-timing stream cases. Assertions check the union-span rates and that an untimed long interval cannot admit a short burst. `stereo-rate-scope/README.md` retains the before/after fixture for the former aggregate-by-max-span behavior; current tests exercise corrected stream-byte/interval-union arithmetic. Root’s extra replay adds reverse-order, nested-overlap and negative-span cases (`stereo-rate-root/final/extra-run.log`: 3 checks).
- **NX direct quality-budget mode:** `tests/bitrate_bbr_budget_test.cpp:85-220` checks compressed byte ratios (25%, 12.5%, 50%), content-ratio changes, mixed quality/network streams, physical-capacity estimate, loss/slow-span backoff, and missing accounting. Root suite log reports 4,346 checks. This is not native two-eye ASTC probe/deadline coverage.
- **NX Warp AIMD asymmetry/missing eye:** `tests/bitrate_nxwarp_test.cpp:296-465` covers missing reports, one-eye survivor-counter drift, loss visibility and eyes paced apart on a clean link. `:467-523` tests loss cuts and bounded recovery. Root log: 31 checks. It concerns NX Warp’s control path and AIMD, not native ASTC BBR probe admission.
- **Current coupled deadline model:** `stereo-rate-coupled/README.md` reports an idealized paired-ready, serialized-eye replay. It covers 500 Mbit/s and 2 Gbit/s assumed capacities and 1,200 modeled frames per trace, but explicitly omits real queue drops, producer waits, per-group pacing, feedback delay, FEC and compression. Its raw traces show temporary periodic-probe service intervals over the nominal frame period. It does not establish actual missed refreshes.

## Deadline-aware setting and missing gate

I found no existing native probe setting that admits/denies an upward probe from predicted paired-eye completion time. In `server/driver/bitrate_controller.h:154-162,339-344`, the ordinary BBR probe is described as gain 1.10 every 8 seconds, lasting 500 ms. `server/driver/bitrate_controller.cpp:1299-1310` starts it when not radio-held, timer elapsed, and bitrate below ceiling. That admission has no paired-eye deadline or queue estimate. In ordinary BBR, late frames affect acute backoff only together with enough loss (`:1130-1137`); they do not independently block a probe. The explicit “decoder lateness blocks upward probes” guard is `quality_mode`-only (`:1331-1335`), so ordinary native/multi-stream mode lacks that guard. The separate 500 ms retry cadence/gain ramp is likewise specific to direct `quality_mode` (`:1283-1289,1303-1308`).

**One useful next gate:** test-only native BBR probe admission in the existing production-helper queue/pacer model, with paired ASTC stream shares, serialized eye readiness (including asymmetric/missing eye), and an explicit nominal frame deadline. Assert that an admitted probe stays within the modeled deadline/backlog bound on a constrained link while a recovered wide link still rediscovers capacity; preserve loss/radio holds and baseline steady-state targets. This would add information beyond the controller’s existing single-link step-up/down tests and the coupled replay’s unconditional probe. Keep it a model/regression gate: it cannot prove live freshness or headset latency. Root owns that model work; this audit does not implement or run it.
