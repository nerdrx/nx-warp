# PC encoder lifecycle gap

Read-only audit of current source `09e7951a6e3273e35dccfacefebdd27303211866`. I read the requested reports at `nx-warp/bench/results/90fps-2026-10-05/continuous/SENDER_OWNED_FRAME_AUDIT.md` (source scope 831aafed) and `.../continuous/fence-attribution/README.md` (historical fence evidence a98d5ac0); neither asserts a current compositor timeout retirement test.

Native ASTC owns per-slot command buffers, fences, block/readback buffers, and validity (`server/encoder/video_encoder_astc.h:19–27`). `present_image` waits that slot fence before recording, then submits behind the compositor semaphore and associates the slot fence (`video_encoder_astc.cpp:236–246, 269–299`); `encode` waits the same fence, reads slot queries and invalidates readback before packing (`:302–325`). The opt-in stereo overlap (`WIVRN_ASTC_PARALLEL_EYES=1`) runs only two independent ASTC encoders concurrently and joins the right-eye future before releasing the image (`server/compositor/compositor.cpp:1640–1644, 1696–1721`). Packet bytes are owned by a `shared_ptr` in sender data (`server/encoder/video_encoder.h:63–69`).

One lifecycle boundary remains source-worthy: compositor command-buffer/query-pool retirement after timeout. `layer_commit` resets its single shared command pool and query pool at `compositor.cpp:838–842`, submits, then waits up to one second on the timeline semaphore (`:1157–1168, 1214–1237`). That signal uses `stageMask=eComputeShader` (`:1151–1155`), so reaching its value does not by itself establish completion of later transfer commands. Vulkan requires all command buffers from a pool to be non-pending before `vkResetCommandPool` (VUID 00040: [command-buffer spec](https://docs.vulkan.org/spec/latest/chapters/cmdbuffers.html#VUID-vkResetCommandPool-commandPool-00040)); semaphore signal scope is stage-limited ([VkSemaphoreSubmitInfo](https://docs.vulkan.org/refpages/latest/refpages/source/VkSemaphoreSubmitInfo.html)). On timeout, `motion_unsafe` blocks estimator reuse/destruction (`:1220–1227, 1284–1290`), but reset at `:838` occurs before `motion_begin` can apply that guard. I found no separate compositor submit fence or prior-generation retirement gate before the next reset. This is a source/spec concern, not a reproduced Vulkan fault or driver diagnosis.

Useful next check: a lifecycle gate that models timeout followed by a later commit and requires explicit completion association before command-buffer/query-pool reset, result reuse, or motion readback. Current successful waits gate query retrieval and motion readback (`:1232–1250`); simply deleting the wait is unsafe. A CPU mock can test state transitions, while Vulkan validation/device execution is needed to establish API correctness, compositor/GPU timing to measure stalls, and Pico validation for user-visible impact.
