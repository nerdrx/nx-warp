# Timeout-to-next-commit retirement proposal

Read-only review at `09e7951a6e3273e35dccfacefebdd27303211866`.

**Recommendation: separate submit fence**, preserving the existing timeline signal at `eComputeShader`. A `vk::raii::Fence` can be created with the same Hpp pattern as ASTC slot fences (`video_encoder_astc.cpp:208`) and passed as the second argument to existing `vk.queue.queue.submit2` (`compositor.cpp:1157–1167`; Hpp API accepts an optional fence). `vk.device.waitForFences` is already used in this source. Add `submission_pending`; set it after successful submit, clear it only after a successful full-fence wait. On timeout set/retain it. At the next `layer_commit`, after current connection/`encode_request` early exits but before `acquire_image()` / `cmd_pool.reset()` (`compositor.cpp:802–813, 838`), if pending poll the fence with timeout zero. If still unsignaled, clear `frame.rendering` and return without acquiring or resetting; if signaled, clear pending and `motion_unsafe`. Create initially signaled or track the initial no-submission state explicitly; reset immediately before each submit. This requires either a bounded full-fence wait at each commit end (may extend the current wait to optional mirror completion) or nonblocking fence polls at the next commit; current compute-signal/query path alone cannot clear pending.

The existing timeline alternative can use the already exposed `vk.device.waitSemaphores(wait_info, 0)` to poll only after a timeout; installed Vulkan-Hpp RAII `Device` exposes that call, while `getSemaphoreCounterValue` is absent from its RAII wrapper. But changing the shared `sem_info.stageMask` to `eAllCommands` delays the semaphore signal used by encoder submissions and mirror until the whole compositor submit finishes. Current encoder waiters override their local stage masks (`video_encoder_astc.cpp:294–296`, `video_encoder_raw.cpp:163`, `video_encoder_nxwarp.cpp:1671,1728`), but that does not advance the shared signal itself. Optional mirror capture is recorded after compositor timestamp query 4 (`compositor.cpp:1129,1136–1147`), so an all-commands signal may extend existing waits to that tail. A distinct retirement timeline avoids that coupling but adds a semaphore and second signal value; a fence is simpler.

On end-wait timeout, skip query retrieval and `send_motion_field` (current branch does so at `:1219–1227`); leave motion unsafe until retirement is confirmed. The current timeline wait uses the compute-stage signal, and query 4 precedes mirror capture, so neither alone guarantees command-buffer retirement (`:1214–1237`). `Queue::submit2` result-checks/throws; commit the timeline candidate value and pending state only after it succeeds. A reset fence after failed submission is unsignaled but non-pending; device-lost remains fatal-state handling. `sem_value` is already non-atomic and written only in `layer_commit`; no lock is visible here, so caller serialization remains an explicit assumption to verify. No runtime/API validation was run.
