# Sampling direction after the held F gate

The [receiver audit](AUDIT.md) establishes that first/last reception values are software-processing timestamps. The completed-frame timestamp follows `decoder_->push_data`. In the native ASTC decoder that call holds its mutex and appends packet bytes (`client/decoder/astc/decoder.cpp:161–188`); it is not the complete GPU decode. Its duration has not been measured here. Queue draining could compress software arrival spans, but that remains an inference rather than a live finding.

The [sender audit](SENDER_SPAN.md) confirms that normal native ASTC shards already carry per-eye frame send endpoints. `SendData` refreshes the terminal-shard send endpoint after prior pacing, immediately before that terminal shard is sent. The earlier function-entry assignment is not the final in-band endpoint. No protocol extension appears necessary for a sender-span experiment; validity and matching still need a gate.

The IETF [Delivery Rate Estimation draft, sections2.2.2–2.2.4](https://www.ietf.org/archive/id/draft-cheng-iccrg-delivery-rate-estimation-02.html#section-2.2.2) describes limiting an acknowledged delivery sample by its corresponding send rate to resist compressed or aggregated acknowledgments. With the same delivered-byte numerator, this uses the longer of send and acknowledgment elapsed intervals. This is a research draft, not a claim of compliance or a direct implementation for NXVC.

**Next bounded experiment:** use native matched frame/eye bytes with separately unioned send and receive intervals; compare the maximum interval duration with D’s receive-only sample. This is an inference from the available metadata and draft, not a demonstrated improvement. Require all contributing byte streams to have valid positive matched send spans before applying a cap; preserve D behavior on zero/missing/reversed metadata. Keep receive-based utilisation and current startup, loss, radio, direct-quality and app-limited policies separate. Do not divide aggregate stereo bytes by one eye’s widest span. Require serial and overlapping eyes, independently shifted clock origins, repaired/late completion and all existing clean recovery/collapse/noisy controls before integration. Pacing or encoder limitation must not be misread as a smaller physical link.

A sender endpoint excludes the last syscall and later repair/FEC traffic; that limitation must remain explicit. No NIC hardware arrival stamp, new runtime measurement, packet policy change, install or live result is established by these audits.
