# Retain useful repair bytes; avoid obsolete requests

The enabled plaintext shard-history byte ring grows from 1 to 2 MiB per encoder; its 4096-entry cap, primary-only retention and ordinary freshly serialized retransmission path are unchanged. Disabling now explicitly moves an empty vector into the ring: the previous `{}` assignment cleared size but retained allocation. The diagnostic reports allocated capacity, so the existing disable check verifies release. This adds 1 MiB of PC storage per enabled eye, not another per-shard copy or a headset pass.

A synthetic 90 Hz two-eye payload sweep uses the actual shard payload budget, optional view/timing serialization, recovery blobs and `shard_history` collection. At 1000 Mbit/s aggregate payload, the old ring keeps only 262/521 shards one frame back and none two frames back with FEC-enabled shard sizes. The 2 MiB ring retains all521 at both ages. At700 Mbit/s, the two-frame-old count grows54/365→365/365. These are byte-retention results, not Wi-Fi delivery or latency measurements. Parity/framing overhead is excluded from the stated payload rates; production's FEC bitrate share is lower. Arbitrary unequal-eye allocation or variable bursts have no fixed retention-time guarantee.

A client stale-NACK suppression prototype was rejected before commit. It passed window tests and would avoid requests for frames the next pump retires, but those requests also feed the server's adaptive-FEC loss estimate. Omitting them reduces `reconstructed + nacked` counts; an incomplete frame still gets a 3% floor, which can understate heavier loss. Preserving recovery behavior matters more than saving these rare control requests. The client NACK timing, retries, skew retirement and age defaults remain unchanged.

The high-rate test includes empty default foveation vectors. ASan/UBSan exposed an existing zero-length memcpy with a null empty-vector data pointer in the generic reader. The shared reader now skips copying zero bytes after checking remaining size; cursor/bounds behavior and nonempty copies are unchanged.

Validation: actual recovery history and window tests, normal and halt-on-error ASan/UBSan; exact synthetic returned payloads and existing overwrite/disabled/spill/rate/bitmap cases. NACK/history tests pass 816 checks normally and with halt-on-error ASan/UBSan; the FEC suite passes 4296 checks with ASan/UBSan. Final server/OpenXR and Android native-library builds pass. No installed APK, property or running live session change is implied.
