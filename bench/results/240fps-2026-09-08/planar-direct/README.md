# PLANAR direct-render evidence

This archive records the standalone native PLANAR renderer on the synthetic
4352×2176 changing-pixel pan fixture. The fixture is approximately 157 Mb/s,
low-complexity, all-PLANAR input; it is not a general stream or live session.
The capture includes no PC encoder, network, XR compositor, or head-motion
pose warp.

`raw-captures.tar.gz` is the sole source archive. It contains the named CSV and
log captures, manifests, validation JSON, and the actual Pico screenshot
`async-capture.png`; it contains no binaries or NXV streams. `summary.json` is
generated by `summarize.py`, which reads CSV members directly from the archive
and reports all-frame and warmup-excluded nearest-rank median/p95/p99/max for
available GPU, total, interval, and arrival-late columns. The paced summary and
trace plots are scientific diagnostics.

![Pico async capture](async-capture.png)

The final paced captures are a 7,200-frame A/B run. `total_ms` is scheduled
arrival to observed completion and is the deadline-miss metric: default runs
recorded 1,432 and 1,254 misses out of 7,176 measured frames; HIGH runs
recorded 664 and 670. This new two-minute result still does not establish 240
FPS. `interval_ms` is cadence jitter/budget exceedance, not deadline success.
Arrival timestamps are CPU observations, while fence timing includes queue
waiting. `interval_ms` includes inter-frame CPU cleanup. CSV output is buffered,
and cold startup/device/pipeline creation is outside the timed window; warmup
must be explicit.

`direct-native-first` is the exact coded-YUV renderer. The flat and compact
arms intentionally discard slopes or restrict the region representation and
are approximation diagnostics. `async-paired*` and `pipeline-validation`
cover the two-slot submission identity checks. `format-paced*` records the
rejected RGB565 experiment; it is not a production result. `direct-validation`
contains exact/rejection validation metadata.

Reproduce the summary with:

```sh
python3 bench/results/240fps-2026-09-08/planar-direct/summarize.py
```

The final Android reproduction uses the built binary and shaders pushed to the
device, with the optional queue-priority environment:

```sh
adb shell 'cd /data/local/tmp/planar-direct && NX_PLANAR_QUEUE_PRIORITY=high NX_PLANAR_TILE=1 NX_PLANAR_PACE_FPS=240 NX_PLANAR_PACE_SPIN=1 NX_PLANAR_ASYNC=1 NX_PLANAR_SPIN=1 NX_PLANAR_REUSE_COMMANDS=1 taskset 80 ./nx-planar-direct-pace pan-7200.nxv . 7200'
```

`final-probe-binaries.json` records matching executable and shader hashes. The
archive also contains current vertex-palette sources and paired captures (GPU
median about 1.36 to 1.26 ms; latency remains inconclusive). The realtime queue
attempt is archived as a rejection with no result.

The probe itself remains restricted to complete all-PLANAR frames. Integrating
it into a decoder would require mixed-frame handling and preservation of the
normal parser/reference semantics.

Generate the summary and plots with:

```sh
python3 bench/results/240fps-2026-09-08/planar-direct/summarize.py
```
