# Store ablations

These are archived D128 measurements from the controlled 2026-09-08 run set.
The summary covers motion frames 25–95 inclusive and reports nearest-rank
median, p95, and p99 for Pass B, GPU, and total time.

`summary.json` is generated by `summarize.py`; `gpu-median.png` is a compact
scientific plot of the GPU medians. `raw-logs.tar.gz` contains the source logs
and `ring-shift.patch` used for the ring-shift arm.
The plot is a diagnostic comparison and includes invalid or inconclusive arms;
it is not a production-performance chart.

Interpretation is deliberately limited:

* `ring-*` compares refresh and ring-shift runs. Ring-shift showed no gain.
* `ring8-*` compares refresh and the four-samples-per-word ring-store
  diagnostic. It showed no gain and produces invalid reference output.
* `ablation-*` includes no-ring and no-predictor diagnostics. Those have
  invalid output and are timing isolation only, not optimization wins.
* `output-*` toggles legacy output stores. The first pair was equal and the
  runs are inconclusive because they were separate clock-variable runs.

The logs are real device captures from the same D128 fixture, but each run was
captured separately; small clock and scheduling differences remain. No new
performance claim should be inferred from this archive alone.

The archived `fused-0-fused.log` and `fused-3-fused.log` runs are the restricted
direct-prediction/store experiment. `fused-conformance2.log` records 161 cases,
3 skips, and 0 failures after restriction. Paired wall medians were 66.278 ms
(control), 64.975 ms (candidate), 63.121 ms (control), and 65.933 ms
(candidate), so the experiment showed no consistent gain and was rejected.
`fused-store.patch` and `legacy-output.patch` preserve the tested changes for
auditability; neither is part of the shipping decoder. Every reported number
in `summary.json` is parsed directly from a log member of the archive by the
bundled script; no hand-entered measurements are included.
