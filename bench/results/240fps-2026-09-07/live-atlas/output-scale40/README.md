# Output scale 0.40 live experiment

This matched exploratory experiment compares the existing R8 reverse baseline
(see [direct R8 handoff](../direct-r8-handoff/README.md)) with an opt-in
output scale of 0.40, producing 864 rather than 1088 pixels per eye. The
probe APK is `b697938fa0abfc9fbdb047c1a02522a6ccae0fca717914b7b45730cddc1f4c02`;
control/reverse use `0582f10bd6a4c45da161981381122ad539b4deab212a1fdb1595ce8db23e8e99`;
server `a7b47b3e164eaa1578774526598911546b00ae83b55ba7a33f874e2504040d82`.

Across active report windows, baseline/probe/reverse medians were renderer
GPU 2.55/1.65/2.60 ms, decoder wall 2.3/2.7/2.2 ms, decoder GPU
1.2/1.4/1.2 ms, copy 0.28/0.29/0.29 ms, and reported fresh sources
88.5/88.25/88 per second. Session gaps remain; these are window means and do
not establish physical FPS. The lower scale reduced one measured display
stage in one arm, with an observed quality tradeoff: both baseline and probe screenshots show scene artifacts, so this does not
attribute them to scale; the probe also shows binocular checkerboard ghosting/block artifacts. It does not establish
quality equivalence or a causal end-to-end speedup, and remains opt-in.

`summary.json` is regenerated by `summarize.py`; `plot.py` creates the linked
plot from the recorded aggregate values. Raw logs, manifests, screenshots,
and `output-scale40.patch` are retained here with SHA256 checksums.

A further direct arm used APK `c55a2fa1e49069a541bdd44f42c9a46f7576455cb800a12c986955321ecebc91` and is retained under `direct/`. Its canonical active-window medians were renderer GPU 1.45 ms, decoder wall 2.0 ms, decoder GPU 1.4 ms, copy 0.01 ms, and 87 reported new sources/s (63.8205 reported sources per wall second); direct targets were active. This remains an exploratory arm under the same session-gap and quality limitations.
