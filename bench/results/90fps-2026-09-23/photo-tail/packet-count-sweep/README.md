# Separate packet-count sweep

This is a separate `crowd500` fixed-quality sweep of 16, 32, 48, and 64 discarded packets after the main frame. It is not the original paired `tail0`/`tail64` report.

| discarded packets | encoder FPS | new-source FPS | app render-loop FPS | predicted runtime ms | holes |
|---:|---:|---:|---:|---:|---:|
| 16 | 89.93 | 86.68 | 89.44 | 47.79 | 0 |

| 48 | 90.00 | 76.45 | 89.44 | 44.92 | 0 |
| 64 | 89.93 | 84.33 | 89.44 | 39.78 | 0 |

The 64-packet setting has the fastest arrival estimate, but 48 packets has the worst fresh-selection rate. These results do not establish an unqualified win; they show a tradeoff under this fixed-quality synthetic workload.

All values are independent 2-second window means. `p95` uses nearest-rank `ceil(0.95*n)-1`. `windows.json` contains sanitized numeric evidence and line citations; `summary.json` contains aggregates; `comparison.png` is regenerated by `rebuild_packet_count.py`. No photos, private previews, absolute source paths, or production changes are included.
